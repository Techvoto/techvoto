# Techvoto production release checklist

Do not mark a line complete without evidence. Production deployment remains unauthorized in this handoff.

## Source and CI

- [ ] Attach the consolidated source to the authorized Git repository and review the diff.
- [ ] Confirm GitHub Actions discovers both workflows at `.github/workflows/`.
- [ ] Frontend: `npm ci`, `npm test`, `npm run lint`, `npm run typecheck`, `npm run build` all pass.
- [ ] Backend: install `requirements.txt`, `makemigrations --check --dry-run`, `manage.py check`, and `manage.py test` all pass.
- [ ] Confirm all committed migrations are present and apply cleanly against a staging PostgreSQL database.
- [ ] Review dependency advisories and pin/lock updates generated by the CI environment.

## Security and configuration

- [ ] Rotate/revoke database credentials, Django `SECRET_KEY`, Paystack secret and JaaS/Jitsi keypair from the supplied export; record operator confirmation without sharing secret values.
- [ ] Confirm no `.env`, SQLite database, private key or credential is in the repository/artifact.
- [ ] Verify Vercel frontend URL and Render API URL; set Vercel `VITE_API_URL` to the verified HTTPS API origin.
- [ ] Configure Render `ALLOWED_HOSTS`, `CORS_ALLOWED_ORIGINS`, `CSRF_TRUSTED_ORIGINS`, `FRONTEND_URL`, and `NUM_PROXIES` from the actual topology.
- [ ] Prefer same-site custom frontend/API domains; verify DNS and TLS certificates.
- [ ] Set `DEBUG=False`, `AUTH_COOKIE_SECURE=True`, a reviewed `SameSite` policy, and only-if-needed cookie domain.
- [ ] Provision PostgreSQL, shared Redis cache, separate Celery broker, SMTP, durable media storage and monitoring.

## Browser and authentication

- [ ] Test current and previous two major releases of Chrome, Edge, Firefox, Safari, iOS Safari and Android Chrome.
- [ ] Confirm Web Locks exists on HTTPS and the two-tab lock smoke harness passes.
- [ ] Verify no-Web-Locks fail-closed path never sends a refresh request.
- [ ] Verify login, registration, CSRF, reload, session expiry/refresh, simultaneous tabs, logout, account switching and file downloads.
- [ ] Verify cookie behavior with Safari tracking prevention enabled under the final same-site topology.

## Payments, live classes and operations

- [ ] Paystack sandbox: checkout initialization, success/failure/cancel return, pending verification, webhook signature, duplicate webhook delivery and idempotent enrollment.
- [ ] Refund lifecycle: request, approval, rejection, processing, success/failure webhook and duplicate delivery.
- [ ] Confirm Paystack production webhook points to the verified API host and required events are enabled.
- [ ] JaaS/Jitsi: rotate keypair, verify token claims, class join window, attendance, end/cancel and invalid-key behavior if enabled.
- [ ] Verify SMTP delivery, Celery retries/worker health, media persistence, health endpoint, logs, alerts and backup/restore procedure.
- [ ] Complete staging smoke test and rollback rehearsal.
- [ ] Obtain explicit release approval before production deployment.
